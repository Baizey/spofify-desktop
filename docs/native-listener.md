# Native listener implementation

`src/main.rs` installs Slint callbacks. The GUI thread never waits for a library read, decoder, artwork request, or playlist write. Account changes advance the shared epoch. Player controls, browser events, MPRIS intents and completed reads are checked against their scope before use.

The sidebar switches between independent sections. History is the initial section, not the parent of Playlists, Saved offline or Settings. Back retraces a drill-down within the current section, including a search and its results. The bottom player is present only while there is a current track, including a paused one.

## Data ownership

| Owner | Data / contract |
| --- | --- |
| `engine`, `socket`, `playback_sync`, `audio`, `player` | Go's account WebSocket with v3 playback JSON. Authenticated admission, confirmed intent plus pending command projection, a device-owned native executor, and measured observations. The Rodio output consumes bounded sources. Displaying a queue never authorizes rendering it. |
| `desk`, `pages`, `replica`, `personal`, `personal_bridge`, `personal_cache`, `actions` | Account-local browser views. Cached playlists and History render before network refresh. Playlist members are installed from complete, scoped snapshot parts; playlist edits travel over the same account socket. Indexed search uses `/search` and its opaque continuation. Album and artist views use the corresponding library detail and child-page endpoints. |
| `presentation`, `media`, `artwork` | Real authenticated artwork, waveform and lyrics. The catalog artwork worker loads the hero and up to 12 leading rows, coalesces duplicates and caches misses. The mini-player requests cover art for its current track; lyrics and waveform are fetched when Now Playing opens. No external artwork/lyrics URL is followed and no lyric is stored in downloads. |
| `preferences` | Device-local density, crossfade and output volume. Density loads from `appearance.json` without applying an old theme value; crossfade and volume keep their separate files `playback.json` and `local-volume.json`. |
| `offline`, `collections`, `saved`, `playlist_pins`, `playlist_pin_store`, `playlist_browser` | Explicit downloads, durable playlist intent and ordered collection membership. Verified media are separate from ephemeral room state and network credentials. |

Online catalog views are capped at 500 rows. Saved views show all local rows; the cache retains at most 24 views and 1,400 rows total; the navigation trail has 40 entries. Navigation cancels superseded reads. Last-good rows survive transient failures and local collection invalidations. A stale search continuation rebuilds from a new result set through the requested depth. Reads and pending rules evaluations have bounded automatic recovery; writes and playback commands are not blindly replayed. Only server-observed qualification contributes to shared History. Desktop persists qualifying local visits without uploading them. A native visit that starts online and finishes detached keeps its progress and merges with a later server entry for that same visit. See `shared-state.md` for the account-socket boundary.

## Remembered sign-in

A typed remembered login admits the same account locally before checking the network. The private Secret Service record binds the previously authenticated origin and account to the startup preference; disk prefill and the Downloads index are never authority. A legacy online-only credential must validate with its original server once before it can be migrated. A definitive rejection retires the remembered capability. Password sign-in and remote sign-out are not automatically repeated.

Startup and connectivity recovery use bounded retries with backoff and never change the manual offline preference. Manual offline blocks application network work, including credential validation and the account socket. **Go online** permits recovery but does not assert that the server is reachable. A single process per private config root owns remembered auth.

## Manual saved music

Save a track or collection while online. Use **Work offline** to browse cached playlists and History and play downloads in queue order, including duplicate entries. A failed download lookup disables playback for unverified rows without replacing their metadata. Recovery restores online services without importing private queue or transport changes or auto-resuming paused playback. Audio is fetched through Go's versioned download endpoints, checked against metadata, size and digest, and stored privately under the exact origin/account scope. Playback verifies the selected recording and decodes from the same opened file. Download storage is limited by the filesystem. Collection manifests are validated page by page without truncating membership. Removing a collection does not delete shared audio files.

Local playback prefers a verified download, including online. Online streams use an authenticated response and a temporary private file, not Saved storage. On disconnect only the current occurrence can drain that stream's buffer; a new occurrence must obtain a new admission. Playback can start once the decoder has the bytes it needs. Seeking ahead of the downloaded portion, or opening a format that reads a tail index, may wait for more data. Desktop’s transfer and PCM buffers are bounded independently of track size. Codecs may retain format-specific metadata such as MP4 sample tables; Desktop does not buffer the complete encoded track.

Desktop stores Offline v2 data in `spofify-personal-v2`, `spofify-downloads-v2`, `spofify-collections-v2` and `spofify-playlist-pins-v2`; it does not read or import v1 offline state. Album and artist saves use the catalog collection index, not the playlist pin store. When network access returns for the same account, pin workers verify and reuse existing downloads. For rule playlists, a non-ready evaluation retains the last ready rows and does not refresh their timestamp. A complete ready evaluation restores shared playback, copying, and download admission. Unpinning works offline and does not delete audio.

Downloads persist across restarts. This is **not** disk encryption or protection from someone who controls the system user account and its keyring. An installed Work offline grant can outlast its server cookie. While disconnected, Desktop cannot learn about remote revocations; a definitive rejection on Go online retires the grant, and local sign-out revokes local access. No passwords, cookies, CSRF tokens, command receipts or socket tickets are written to the offline index.

## Verification environment

Use the normal locked Cargo test command. Filesystem tests require a private Linux directory that supports owner/mode checks, file locking, hard links and symlinks. On FUSE-mediated build workers use a fresh `TMPDIR` on private tmpfs and remove it afterwards. The MPRIS session-bus round-trip test is intentionally opt-in (`dbus-run-session -- cargo test --locked desktop_controller_round_trip -- --ignored`). The opt-in `engine::cross_native_tests::desktop_cross_native_play_and_handoff` and `engine::cross_native_tests::desktop_cross_native_conditional_seek` run with the Go/Android `pair.py` runner, a disposable Go account, the real v3 transport and a deterministic Rodio mixer. The [historical Python v1 socket scenarios](../scripts/acceptance/README.md) are incompatible with the current socket. Production builds do not enable inspection.
